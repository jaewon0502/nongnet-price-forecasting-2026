# 모델 구성과 검증 회고

README에서 간단히 다룬 내용을 조금 더 자세히 적었습니다. 대회 개요와 평가식은 [대회 기록](competition-record.md)에 있습니다.

## 15개 칸의 최종 구성

| 품목 | 10일 | 2순 뒤 | 3순 뒤 |
|---|---|---|---|
| 배추 | Chronos-2 다변량, 중앙값(q0.50) | LightGBM q0.30 | LightGBM q0.60 |
| 무 | LightGBM과 Chronos-2의 산술 평균 | LightGBM q0.45 | LightGBM q0.40 |
| 양파 | Chronos-2 단변량, q0.60 수준 | LightGBM q0.55 | LightGBM L1 |
| 깐마늘 | 마지막 관측 가격 | 마지막 관측 가격 | 마지막 관측 가격 |
| 건고추 | 마지막 관측 가격 | 마지막 관측 가격 | 마지막 관측 가격 |

10일 예측은 다음 열흘의 일별 가격이 필요하고, 2순·3순 뒤 예측은 한 순의 평균 가격 하나만 필요합니다. 출력 형태가 다르기 때문에 같은 품목이라도 기간마다 모델을 따로 골랐습니다.

Chronos-2는 공개 체크포인트를 미세조정 없이 썼고, LightGBM은 분위수(quantile)나 L1 손실로 학습했습니다. 이 손실은 대회 지표인 MAPE와 같은 식이 아니므로, 학습 목표와 최종 평가를 구분해서 다뤘습니다.

## 평가식을 먼저 정확히 구현했습니다

모델을 비교하기 전에 대회 채점 방식과 똑같이 점수를 내는 로컬 평가부터 만들었습니다. 신경 쓴 부분은 세 가지입니다.

- 실제 가격이 없는 날(휴장일 등)은 0이나 보간값으로 채우지 않고 계산에서 뺐습니다. 제출해야 하는 날짜 수와 실제로 채점되는 날짜 수가 다릅니다.
- 품목별 점수를 표시 자릿수로 먼저 반올림한 뒤 합치지 않았습니다. 중간 반올림은 순위가 갈리는 미세한 차이를 만들 수 있습니다.
- 가중치를 풀어 보니 10일 예측의 배추·무·양파가 종합 점수의 절반을 차지했습니다. 이후 실험 순서를 정하는 기준이 됐습니다.

## 10일 예측을 바꾼 이유와 반대 증거

마지막 개선에서는 10일 예측의 배추·양파를 Chronos-2로 바꾸고, 무는 기존 LightGBM과 Chronos-2를 반씩 섞었습니다. 2순·3순 뒤와 깐마늘·건고추는 그대로 두어 바뀐 부분의 효과만 볼 수 있게 했습니다.

무에서 섞는 효과가 난 것은 두 모델이 서로 반대 방향으로 틀리는 구간이 있었기 때문입니다. 하지만 2025년 한 해에서 그랬다는 것만으로 섞는 방식이 늘 낫다고 말할 수는 없습니다. 실제로 같은 구성을 과거 연도에 적용하면 결과가 반대였습니다.

| 10일 품목 | 기존 구성 (2022\~2024) | 최종 구성 (2022\~2024) |
|---|---:|---:|
| 배추 | 14.3654% | 15.4881% |
| 무 | 15.6430% | 16.3035% |
| 양파 | 8.2178% | 9.0289% |

세 품목 모두 과거 성적이 나빠졌습니다. 게다가 Chronos-2의 사전학습 자료에 2022\~2024년 가격 패턴이 섞였는지 확인하지 못했기 때문에, 이 과거 비교도 엄밀한 독립 검증은 아닙니다.

무엇보다 최종 조합은 2025년 채점 결과를 본 뒤에 골랐습니다. 평가 결과에 영향을 받지 않은 선택이라고 말할 수 없고, 대회 규정의 평가자료 이용 제한에도 걸릴 수 있습니다. 다음에는 후보와 선택 규칙을 먼저 정해 두고, 선택에 쓰지 않는 마지막 평가 구간을 따로 남기겠습니다.

## 재현 검증에서 발견한 차이

대회 검증은 인터넷이 끊긴 CPU 환경에서 이뤄지기 때문에, 비슷한 조건을 만들어 제출 패키지를 다시 돌렸습니다.

- **Linux x86_64, 4 CPU, RAM 6GiB, 스왑 없음, 네트워크 차단:** 12개 기준일 전체 추론 68.4초, 반복 실행 68.0초. 최대 메모리 약 2.35GiB. 같은 환경에서 반복한 CSV·XLSX 출력은 바이트 단위로 같았습니다.
- **Mac과 Linux 비교:** 600개 예측값 중 98개가 달랐고 최대 차이는 0.0148원이었습니다. 이 차이를 맞추려고 예측값을 고치지 않고 두 결과를 모두 보관했습니다.
- **배치 크기 변화:** 기준일 2개를 묶어 돌릴 때와 12개를 묶어 돌릴 때 배추 한 값이 0.0114원 달랐습니다.

평균 점수가 소수 넷째 자리까지 같아도 예측값 하나하나가 같다는 뜻은 아니었습니다.

후속으로 Mac에서 재학습과 추론을 다시 했을 때 프로그램은 정상 종료됐지만, 환경 검사는 `narwhals` 패키지 버전 차이(2.27.1, 명세는 2.26.0)로 실패했습니다. 학습이 끝까지 돌았다는 것과 환경 전체가 명세와 같다는 것은 별개였습니다. 최종 10일 패키지를 Linux에서 재학습부터 추론까지 처음부터 다시 돌린 기록은 아직 없습니다.

## 날짜와 반올림도 모델의 일부였습니다

무의 결합은 LightGBM의 소수 넷째 자리 출력과 Chronos-2의 원시 실수를 먼저 평균한 뒤 마지막에 반올림합니다. Chronos-2 출력을 먼저 반올림하면 33개 값이 달라집니다.

배추·양파에 쓴 Chronos-2 설정은 기준일 D부터 D+9까지에 해당하는 출력을 D+1\~D+10 제출 칸에 넣는 방식입니다. 무는 날짜에 맞는 인덱스를 씁니다. 배추·양파의 한 칸 어긋남을 올바른 정렬 방법이나 다른 기간에서 검증된 방법으로 보지 않습니다. 이 일로 입력 기준일, 모델 출력 인덱스, 제출 날짜를 따로 대조해야 한다는 것을 배웠습니다.

## 다음 프로젝트에서 바꿀 것

1. 학습, 모델 선택, 최종 평가에 쓰는 자료를 처음부터 나누고 선택 기준을 먼저 기록합니다.
2. 품목·기간별로 단순한 기준선을 두고, 복잡한 모델이 그보다 얼마나 나은지로 판단합니다.
3. 최종 패키지는 실제 검증 환경과 같은 조건에서 재학습부터 추론까지 한 번에 확인합니다.
4. 수치 차이가 생기면 크기와 함께 원인과 재현 조건을 기록합니다.
5. 좋은 결과와 불리한 결과를 함께 남깁니다.
