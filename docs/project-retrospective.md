# 모델 구성과 검증에서 내린 판단

## 문제를 품목과 기간으로 나누기

다섯 품목을 세 기간으로 예측하므로 총 15개의 품목·기간 조합을 다뤘습니다. 단기는 일별 가격을, 장기는 해당 순의 관측일 평균가격을 예측합니다. 같은 가격 계열이라도 필요한 출력의 형태가 달라 하나의 모델을 모든 조합에 그대로 적용하지 않았습니다.

| 품목 | 10일 | 2순 후 | 3순 후 |
|---|---|---|---|
| 배추 | Chronos-2 다변량 q0.50 | LightGBM q0.30 | LightGBM q0.60 |
| 무 | LightGBM·Chronos-2 산술 평균 | LightGBM q0.45 | LightGBM q0.40 |
| 양파 | Chronos-2 단변량 q0.60 평균 수준 | LightGBM q0.55 | LightGBM L1 |
| 깐마늘 | 마지막 관측 가격 | 마지막 관측 가격 | 마지막 관측 가격 |
| 건고추 | 마지막 관측 가격 | 마지막 관측 가격 | 마지막 관측 가격 |

Chronos-2는 고정 체크포인트를 미세조정 없이 사용했습니다. LightGBM에는 과거 가격을 이용한 학습을 적용했습니다. Quantile·L1 학습 손실이 공식 평가 지표 MAPE와 같은 식인 것은 아니므로, 모델의 학습 목표와 최종 평가를 구분했습니다.

## 평가를 먼저 정확하게 계산하기

품목별 MAPE를 계산한 뒤 배추·무·양파 각 2, 깐마늘·건고추 각 1.2의 가중치를 적용하고 합계 8.4로 나눕니다. 이어 세 기간을 70%·15%·15%로 합산합니다. 따라서 단기 배추·무·양파의 종합 비중은 `0.70 × 6 / 8.4 = 0.50`입니다.

실제 가격이 없는 날짜는 평가에서 제외했습니다. 휴장일 등을 0이나 보간값으로 채워 정답처럼 사용하지 않았고, 출력해야 하는 예측 날짜와 실제 평가에 들어가는 날짜의 수를 구분했습니다. 개별 점수를 표시 자릿수로 반올림한 뒤 합산하는 방식도 피했습니다.

## 모델을 바꾼 이유를 결과의 범위 안에서 설명하기

최종 로컬 비교에서는 단기 배추·양파에 Chronos 단독을 사용하고 무에 50:50 산술 평균을 적용한 구성이 비교 대상보다 낮은 오차를 보였습니다. 기존 장기 구성과 단기 깐마늘·건고추는 유지해 변경의 영향을 구분했습니다.

무에서는 두 모델의 반대 방향 오차가 일부 상쇄됐습니다. 다만 특정 평가 구간에서 더 낮은 오차를 보였다는 사실만으로 결합의 일반적인 우월성을 설명할 수는 없습니다.

| 단기 품목 | 이전 구성의 2022~2024 MAPE | 선택 구성의 MAPE |
|---|---:|---:|
| 배추 | 14.3654% | 15.4881% |
| 무 | 15.6430% | 16.3035% |
| 양파 | 8.2178% | 9.0289% |

과거 비교에서는 세 품목 모두 악화됐습니다. 또한 해당 Chronos 체크포인트와 각 과거 평가 연도 사이의 사전학습 자료 독립성을 새로 확인한 결과가 아닙니다. 이 비교를 엄격한 독립 검증으로 제시하지 않습니다.

최종 조합은 2025년 평가 결과를 확인한 뒤 선택한 것이므로, 평가 결과의 영향을 받지 않은 모델 선택으로 설명할 수 없습니다. 다음 프로젝트에서는 후보 범위와 선택 규칙을 먼저 정하고, 모델 선택에 쓰지 않는 마지막 평가 구간을 별도로 유지하는 것을 우선 과제로 삼겠습니다.

## 실행 재현에서 발견한 차이

로컬 Linux x86_64 환경에서 전체 추론은 68.379초, 반복은 67.964초였고 최대 cgroup 메모리는 2,520,494,080바이트였습니다. 같은 환경과 같은 사례 묶음의 CSV·XLSX는 바이트 단위로 일치했습니다.

반면 Mac과 Linux 사이에는 600개 예측 중 98개가 달랐고 최대 절대 차이는 0.0148이었습니다. 두 사례 묶음과 열두 사례 묶음을 비교할 때는 배추 한 값이 0.0114 달랐습니다. 평균 점수나 화면 표시 자릿수가 같다는 이유만으로 예측값이 완전히 재현됐다고 말할 수 없었습니다.

후속 Mac 재학습과 추론은 종료 코드 0으로 완료됐지만, 환경 검사는 `narwhals 2.27.1`과 명세 `2.26.0` 차이로 실패했습니다. 학습 실행 성공과 전체 환경 검증 통과는 별개의 결과입니다. 최종 단기 패키지의 Linux 전체 재학습부터 추론까지 수행한 새로운 증거는 이 공개 시점에 없습니다.

## 날짜와 반올림까지 모델의 일부로 다루기

무의 결합은 기존 LightGBM의 소수 넷째 자리 출력과 Chronos 원시 실수를 평균한 뒤 최종 값을 반올림합니다. 구성요소를 먼저 모두 반올림하면 같은 값이 보장되지 않습니다.

배추·양파의 선택된 Chronos 설정은 D~D+9에 해당하는 출력을 D+1~D+10에 배정하는 규약을 유지합니다. 무는 날짜에 맞는 인덱스를 사용합니다. 배추·양파의 한 칸 차이는 올바른 정렬의 예시나 새로운 기간에서 유효성이 입증된 방법으로 제시하지 않습니다. 이 경험을 통해 입력 기준일, 출력 인덱스, 제출 날짜를 별도로 대조해야 한다는 점을 배웠습니다.

## 다음 프로젝트에 적용할 개선

1. 학습·모델 선택·최종 평가에 사용하는 자료를 구분하고 선택 기준을 먼저 기록합니다.
2. 품목과 기간별 기준선을 유지해 복잡한 모델의 추가 효과를 비교합니다.
3. 운영 환경과 같은 조건에서 최종 패키지의 재학습과 추론을 처음부터 끝까지 확인합니다.
4. 수치 차이를 발견하면 오차 크기뿐 아니라 원인과 재현 조건까지 기록합니다.
5. 좋은 결과와 반대되는 결과를 함께 남겨, 설명의 범위를 실제 근거에 맞춥니다.
