# 프로젝트 Q&A

이 프로젝트에 대해 받을 수 있는 세 가지 질문에 답했습니다. 수치와 근거는 [README](../README.md)와 [모델 구성과 검증 회고](project-retrospective.md)에 있습니다.

<a id="judgment"></a>
## 1. 판단 — “왜 Chronos-2와 LightGBM을 함께 사용했나요?”

품목과 예측 기간에 따라 적합한 방법이 다를 것이라고 생각했습니다. 그래서 하나의 모델로 전체를 교체하기보다, 품목별로 기존 모델과 새 후보의 예측 오차를 비교하는 방향으로 접근했습니다.

평가 구조상 10일 예측이 전체 점수의 70%였고, 그중 배추·무·양파가 전체의 50%를 차지했습니다. 이 부분의 개선이 중요했습니다. 비교한 2025년 결과에서는 배추와 양파는 Chronos-2 단독이 유리했고, 무는 LightGBM과 Chronos-2를 반씩 섞었을 때 오차가 더 낮았습니다. 서로 다른 방향의 오차가 일부 상쇄됐기 때문입니다. 장기 예측은 기존 LightGBM을 유지했습니다.

이 경험으로 모델의 이름이나 복잡도보다, 문제를 나누고 각 방법의 오차를 비교하는 판단이 중요하다는 것을 배웠습니다. 다만 이 결과가 다른 기간에서도 유지되는지는 별도로 검증해야 합니다.

<a id="validation"></a>
## 2. 검증 — “좋은 점수가 실제 예측 능력을 보여준다고 볼 수 있나요?”

확인한 성과와 아직 확인하지 못한 부분을 구분해서 설명하고 있습니다. 기준일 이후 정보가 입력에 들어가는지, 같은 모델과 입력으로 예측값이 재현되는지 확인했습니다. 같은 Linux 환경의 반복 실행에서는 결과가 일치했지만, 운영체제나 배치 조건이 달라지면 미세한 차이가 생기는 것도 확인했습니다.

성능 검증에는 중요한 한계가 있었습니다. 최종 조합을 선택할 때 이미 확인한 2025년 평가 결과가 영향을 줬습니다. 따라서 그 점수를 독립적인 미관측 데이터의 성능으로 설명할 수는 없습니다. 과거 기간을 비교했을 때는 새 단기 구성이 오히려 나빠진 결과도 있었습니다.

여기서 학습에 정답을 넣지 않는 것만으로 모델 선택의 독립성이 확보되지는 않는다는 점을 배웠습니다. 다음 프로젝트에서는 시간 순서대로 학습·선택·최종 평가 구간을 나누고, 마지막 평가 구간은 선택 과정에서 보지 않도록 설계하겠습니다.

<a id="contribution"></a>
## 3. 기여 — “AI가 코드를 작성했다면 본인은 무엇을 했나요?”

Codex와 Claude를 모델 구현, 반복 실험, 오류 수정, 검증 기록 작성에 적극적으로 활용했습니다. 제 역할은 비교할 방향을 제시하고, 결과를 보면서 다음 실험과 확인할 사항을 결정하는 것이었습니다.

구체적으로 품목과 예측 기간마다 다른 모델을 사용할 수 있다고 제안했고, 처음에 제외했던 앙상블과 블렌드를 다시 검토하도록 했습니다. LightGBM으로 성능이 좋아진 뒤에도 Chronos-2를 다시 비교해 보자고 요청했습니다. 또 점수가 좋아졌을 때 어떤 데이터를 기준으로 선택했는지, 규정 해석과 실제 코드가 맞는지, 날짜가 바뀌어도 실행되는지를 계속 확인하도록 했습니다.

제가 기여한 부분은 문제를 구체화하고, 비교 방향을 정하고, AI가 내놓은 결과에 추가 확인을 요구한 과정입니다. 동시에 AI가 제시한 설명을 받아들이는 데서 끝나지 않고, 선택 근거와 검증의 한계까지 제가 이해해야 한다는 점을 배웠습니다.
